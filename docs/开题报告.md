# 开题报告

# 一、作业概述

本作业面向食物图像理解与视觉语言生成任务，研究如何从单张食物图像中提取视觉语义信息，并分别生成自然语言食物描述和满足预定义 Schema 的结构化膳食记录。作业首先基于经典 Encoder-Decoder 图像描述框架，实现并比较 CNN、循环神经网络、注意力机制、Transformer、图神经网络以及 Vision Transformer 等不同视觉语言建模方法；随后进一步引入预训练视觉语言大模型，通过参数高效微调完成食物名称、重量、热量及三大营养素等信息的结构化生成，并研究直接生成与分阶段结构化生成策略之间的差异。

在此基础上，进一步开展 CIDEr-D 奖励驱动的强化学习微调、LLM-as-Judge 描述质量评价，以及结合独立重量模型和营养数据库的工具辅助营养估计实验。最终形成统一的数据处理、模型训练、推理和评测流程，使不同方法能够在明确记录的数据划分、训练配置和评价标准下进行可重复比较。

# 二、任务描述

本课程设计围绕食物图像描述、结构化膳食记录生成和营养估计展开，并研究基于大模型的描述质量评价。

任务一以 Food-500 Cap 数据集为基础，输入一张食物图像并生成自然语言描述。作业实现并比较五类图像描述模型，使用 BLEU、METEOR、ROUGE-L、CIDEr-D、SPICE 五种指标进行评价。[11]

具体包括以下五种模型：

| 模型 | 视觉表示 | 文本生成模块 | 主要研究内容 |
|---|---|---|---|
| Model 1 | ResNet-50 全局特征 | GRU Decoder | 建立经典 CNN-RNN 基线 |
| Model 2 | ResNet-50 网格特征 | 视觉自注意力 + 加性注意力 + GRU | 研究局部视觉区域和显式注意力的作用 |
| Model 3 | ResNet-50 网格特征 | Transformer Encoder + Decoder | 研究全注意力序列建模 |
| Model 4 | 图结构网格特征 | GAT + Transformer Decoder | 研究食物局部区域之间的空间关系建模 |
| Model 5 | ViT-B/16 Patch 特征 | Transformer Decoder | 比较 CNN 与视觉 Transformer 表示能力 |

五种模型统一使用数据划分、图像预处理、文本词表、模型选择规则以及 Greedy/Beam Search 解码设置；训练超参数的模型差异通过配置明确记录，以尽可能保证模型结构比较的公平性。

任务二要求从食物图片生成满足预定义 Schema 的结构化 JSON，其中至少包含食物名称 `items`、总重量 `total_weight_g`、总热量 `total_calories_kcal` 以及蛋白质、脂肪和碳水化合物三个营养字段，并要求比较自行实现的图像描述模型与经过全量微调或参数高效微调的多模态预训练模型。评价采用任务一文本指标以及 F1、MSE 等结构化指标。[11]

本作业针对任务二设计以下四组实验：

**方法 A：自建图像描述模型。** 从任务一中选取验证集 CIDEr-D 表现较好的模型，将文本目标替换为规范化 JSON 序列，使用独立的可逆字符级 Tokenizer 保留 JSON 标点、小数和中文字符，使其直接学习从图像到完整膳食记录的映射。

**方法 B：Qwen3-VL-4B + LoRA 直接生成。** 使用 `Qwen/Qwen3-VL-4B-Instruct` 作为预训练视觉语言模型，在教学云平台提供的 Nutrition5k 数据上进行 LoRA 参数高效微调，通过固定 Prompt 一次生成完整 JSON。当前官方模型仓库提供 Qwen3-VL-4B-Instruct，并支持通过 Transformers 进行 image-text-to-text 推理，因此能够直接接入本作业的多模态训练框架。[Hugging Face](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct/tree/main)

**方法 C：Qwen3-VL-4B + LoRA 两阶段生成。** 使用与方法 B 相同的模型、训练数据和共享 LoRA Adapter，但将推理任务分解为两个阶段。第一阶段识别食物组成并预测各项重量，第二阶段根据图像和第一阶段结果预测总重量、热量和三大营养素，最后通过确定性代码完成 JSON 合并和格式校验。通过与直接生成方法比较，可以研究“语义实体识别”和“连续数值估计”解耦是否有利于结构化输出。

**方法 D：Qwen2.5-VL-3B + LoRA。** 使用 `Qwen/Qwen2.5-VL-3B-Instruct` 作为模型代际和参数规模对照。Qwen2.5-VL 本身具有视觉理解、视觉定位以及结构化信息提取能力，因此适合作为较小规模视觉语言模型基线。[Hugging Face](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)

任务二另设两项补充对照：一是使用不加载 LoRA Adapter 的原始 Qwen 模型进行 zero-shot 生成，分析领域微调的作用；二是复用已训练的 Adapter，先生成完整 JSON 草稿，再结合原图进行一次草稿复核，分析增加推理步骤对输出质量和成本的影响。两项实验分别与对应模型的 LoRA 直接生成结果比较。

此外，完成三项选做实验：选做一采用 SCST 对任务一的 ViT+Transformer 进行 CIDEr-D 策略梯度微调；选做二使用 LLM-as-Judge 评价五种模型的描述并分析其与传统指标的一致性；选做三构建单图像营养估计 Agent，比较同一视觉语言模型直接生成与调用重量、营养工具的结果。具体技术方案见第五节。

# 三、预期目标

本作业首先需要完成一个完整、可复现的食物图像描述实验框架。对于 Food-500 Cap 数据集，实现统一的数据转换脚本，将原始数据转换为训练集、验证集和测试集 Manifest，同时建立统一词表和图像预处理流程。论文介绍的数据集包含约 24,700 张食物图片、494 个类别，描述涉及食材、形状、颜色等细粒度属性。[arXiv](https://arxiv.org/abs/2308.03151) 实际实验读取 Hugging Face Parquet 版本，以图像内容哈希合并重复记录及其参考描述，保留官方测试来源，移除训练来源中与测试图像重复的内容，再划分训练集与验证集。各划分的实际数量和去重统计以生成的 `dataset_info.json` 为准，实验记录同时保留数据版本及清单指纹；历史实验若使用不同清单，分别说明其来源。

在模型方面，预期完成五种图像描述模型的独立实现。除 ResNet-50、ViT-B/16 等预训练视觉编码器允许直接调用外，项目基于 PyTorch 标准模块和张量操作，自行搭建视觉投影层、注意力模块、GRU Decoder、Transformer Encoder/Decoder 以及 GAT 等核心生成组件。所有模型至少能够完成训练、验证、Greedy Search 和 Beam Search 推理，并统一记录模型参数量、训练耗时、推理耗时和显存占用。

评价方面，预期建立统一的图像描述评测模块，一次运行即可计算 BLEU、METEOR、ROUGE-L、CIDEr-D 和 SPICE。课程材料中指出，BLEU主要从 n-gram 精确率评价生成文本，METEOR进一步考虑词级匹配，ROUGE-L基于最长公共子序列，CIDEr利用 TF-IDF 对 n-gram 进行加权，而 CIDEr-D进一步加入长度及重复惩罚；SPICE则将描述转换为场景图，从语义对象、属性和关系层面评价生成结果。[11]

任务二预期建立统一的膳食 JSON Schema、Parser 和 Validator，并完成自建模型、Qwen3-VL 直接生成、Qwen3-VL 两阶段生成以及 Qwen2.5-VL 对照实验，同时补充 zero-shot 与草稿复核实验。最终至少统计食物名称 micro-F1、macro-F1，各营养数值字段 MSE 及有效预测覆盖率、JSON 解析率、Schema 有效率、字段完整率和重量一致性误差。

选做实验预期完成交叉熵模型与 SCST 模型的配对比较、LLM 评分与传统指标的相关性分析，以及直接生成与工具辅助营养估计的对照。营养 Agent 另报告五个数值字段的 MAE、失败率、数值覆盖率、推理耗时和模型调用成本，分析各组件对最终结果的影响。

作业将在统一实验条件下综合分析不同视觉表示、生成网络以及结构化生成策略的特点，例如全局特征与局部特征的区别、GRU 和 Transformer 的区别、图结构建模的作用、CNN 与 ViT 的差异，以及传统小型图像描述模型与预训练视觉语言大模型之间的性能和计算成本差异。

# 四、相关工作

图像描述生成是计算机视觉与自然语言处理相结合的典型视觉语言任务。早期深度学习方法通常采用 Encoder-Decoder 架构，即首先通过 CNN 将图像编码为视觉特征，然后利用循环神经网络逐词生成描述。Vinyals 等提出的 *Show and Tell* 是这一范式的代表工作，通过 CNN 提取图像表示并使用循环网络最大化给定图像条件下描述文本的生成概率，奠定了神经网络图像描述模型的基本结构。[arXiv](https://arxiv.org/abs/1411.4555)

仅使用单个全局图像向量难以描述复杂图像中的多个视觉区域，因此后续工作逐渐引入视觉注意力机制。*Show, Attend and Tell* 在生成不同单词时动态关注不同的视觉区域，使模型可以根据当前文本状态选择与词语相关的局部图像特征，并通过注意力可视化展示文本和视觉区域之间的对应关系。[arXiv](https://arxiv.org/abs/1502.03044) 本作业的 Model 2 对应这一类“局部视觉表示 + 注意力 + 循环解码”的基本技术路线。

Transformer 的提出进一步改变了文本生成模型的主流结构。Transformer完全依靠自注意力机制处理序列，可以直接建模长距离依赖，并具有较好的训练并行性。[arXiv](https://arxiv.org/abs/1706.03762) 随后 Vision Transformer 将图像划分为 Patch 并将其视作视觉 Token 序列，使纯 Transformer 视觉编码成为可能。[arXiv](https://arxiv.org/abs/2010.11929) 在图像描述领域，CPTR进一步将图像和文本均作为序列处理，通过完整 Transformer 网络执行图像描述生成。[arXiv](https://arxiv.org/abs/2101.10804) 因此，本作业设置 CNN+Transformer 和 ViT+Transformer 两种模型，用于比较传统卷积视觉表示与 Patch Token 表示之间的差异。

除序列建模外，图像中的视觉区域还具有明显的空间和语义关系。例如，一道菜中的肉类、配菜、酱汁和餐具并不是彼此独立的区域。Graph Attention Network 通过注意力机制为不同邻居节点分配不同聚合权重，可以处理图结构数据中的局部关系。[arXiv](https://arxiv.org/abs/1710.10903) 基于这一思想，本作业的 Model 4 将二维视觉网格位置作为图节点，根据八邻域构建边，通过两层 GAT 进行局部信息传播，再利用 Transformer Decoder 生成食物描述，从而研究显式空间关系建模是否能够改善细粒度描述。

在食物领域，Food-500 Cap 针对通用视觉语言模型在专业食物场景中的能力不足建立了细粒度图像描述基准，其中描述包含食材、形态、颜色等信息。该工作发现，通用视觉语言模型在食物领域的表现明显弱于其在一般视觉场景中的表现，说明针对特定食物领域的数据和模型研究仍具有实际意义。[arXiv](https://arxiv.org/abs/2308.03151)

另一方面，近年来视觉语言预训练模型已经从传统的固定图像编码器和文本解码器逐渐发展为统一多模态生成模型。Qwen2.5-VL 等模型能够处理不同尺寸图像并直接进行视觉理解和结构化信息生成。[arXiv](https://arxiv.org/abs/2502.13923) 对此类模型进行全量训练成本较高，因此本作业采用 LoRA 进行参数高效微调。LoRA 的基本思想是在冻结预训练参数的基础上，在部分线性层中加入低秩可训练矩阵，从而大幅减少需要更新的参数规模。[arXiv](https://arxiv.org/abs/2106.09685) 这也使 Qwen3-VL-4B 等视觉语言模型能够在本作业现有 GPU 条件下进行较低成本的领域适配。

基于序列级评价指标优化的图像描述研究中，Self-critical Sequence Training（SCST）将当前模型的解码结果用作奖励基线，通过 REINFORCE 策略梯度直接优化不可微的描述评价指标。[13] 本作业将其作为交叉熵训练后的微调方法，考察优化 CIDEr-D 后其他文本指标的变化。

营养估计可拆分为视觉重量回归与食物营养密度检索。DINOv2 提供自监督预训练视觉特征，本作业使用其 Small 模型作为冻结的特征提取器，再训练轻量 Ridge 回归器预测重量。[14] 食物营养密度采用 USDA FoodData Central 的固定版本数据，按食品记录检索后进行确定性计算，使视觉估重与营养换算能够分别检查和评价。[15]

# 五、技术方案

整体采用“**数据层—模型层—生成层—评测层**”四层结构。图像描述、膳食 JSON 生成和营养 Agent 保持独立的实验入口与结果目录，共用数据读写、配置和评价工具。

数据层首先实现两个独立的数据适配器。Food-500 Cap 数据准备模块读取 Parquet 中的图像和描述，按图像内容哈希去重、合并参考描述并处理跨划分重复后，生成统一的 `train.jsonl`、`val.jsonl`、`test.jsonl`、`vocab.json` 和 `dataset_info.json`。任务二使用教学云平台提供的 Nutrition5k 数据，保留原始训练、验证和测试划分及重量、营养标签，并将原始字段统一转换为内部 Schema。图片路径等数据配置通过 YAML 管理。任务一词表仅从训练集建立，并随模型保存，验证和测试阶段固定使用。

任务一训练阶段使用统一 Dataset、Tokenizer 和训练循环。视觉编码器默认使用 ImageNet 预训练参数并冻结，在统一的基本训练设置下分别训练五种文本生成网络。Model 1 提取 ResNet-50 全局特征并作为 GRU 的视觉条件；Model 2 保留二维网格特征，先进行视觉自注意力建模，再由加性注意力在每个时间步计算文本状态与局部视觉区域之间的相关性；Model 3 将网格特征映射为视觉 Token，加入二维位置编码，并通过 Transformer Encoder 和自回归 Transformer Decoder 完成生成；Model 4 将二维网格构造为八邻域图，经过两层 GAT 聚合，再作为 Transformer Decoder 的视觉 Memory；Model 5 去掉 ViT-B/16 的 CLS Token，使用 Patch Token 作为视觉序列，直接连接 Transformer Decoder，不额外叠加视觉 Transformer Encoder。

训练阶段采用 Teacher Forcing 和 token-level Cross Entropy Loss，并按验证集 CIDEr-D 保存最佳模型。推理阶段统一提供 Greedy Search 和 Beam Search，所有模型使用一致的最大生成长度、特殊 Token 和 Beam Size。测试阶段将所有预测统一保存为：

```json
{
  "image_id": "xxx",
  "references": ["reference caption"],
  "prediction": "generated caption"
}
```

随后一次性计算 BLEU、METEOR、ROUGE-L、CIDEr-D 和 SPICE，避免不同模型采用不同评价实现造成误差。

任务二首先定义严格的结构化输出 Schema，例如：

```json
{
  "items": [
    {
      "name": "food",
      "weight_g": 64.0
    }
  ],
  "total_weight_g": 152.0,
  "total_calories_kcal": 103.3,
  "protein_g": 2.9,
  "fat_g": 6.9,
  "carbohydrate_g": 10.6
}
```

所有模型生成结果均保留原始文本，评测阶段不进行自动纠错。Parser 和 Validator 分别负责 JSON 解析和 Schema 校验，检查必需字段、字段类型、非负有限数值以及未定义字段，数值不接受 bool、NaN 或 Infinity；各项重量之和与总重量的偏差单独统计，不作为 Schema 错误。预测 JSONL 保存原始输出、解析结果和错误信息，评价指标另存 JSON 文件，并记录运行配置。两阶段生成与草稿复核额外保留各阶段输出，Agent 额外保存工具调用轨迹。

Qwen3-VL 和 Qwen2.5-VL 使用 LoRA 参数高效微调，不进行量化，优先采用 BF16。LoRA主要插入注意力相关线性投影层，在实际实现时根据模型模块名称确定具体 `target_modules`。模型主干权重保持冻结，仅保存 LoRA Adapter，从而减少训练显存和最终提交文件体积。

针对 Qwen3-VL，将 `direct/items/nutrients` 三类指令混合训练为一个共享 LoRA Adapter；直接生成和两阶段生成使用同一 Adapter，控制模型、训练数据和权重不变，只改变推理任务分解方式，比较“一次生成完整 JSON”和“两阶段生成实体与数值”两种方案。该实验可以较明确地将性能差异归因于结构化生成策略，而不是模型参数规模差异。

zero-shot 实验直接加载原始 Qwen 模型，不加载 Adapter，使用与对应 LoRA 实验一致的数据、直接生成 Prompt 和评价流程。草稿复核实验则复用已有 Adapter，先生成完整 JSON，再根据原图、草稿和检查提示进行一次复核；真实标签不参与复核，评测仍保留无效输出和失败记录。

选做一采用 **SCST 强化学习微调**。从任务一 ViT+Transformer 的交叉熵训练检查点初始化，冻结视觉编码器，仅更新文本解码器。每批由当前策略采样描述，并生成 greedy 描述作为基线；以两者 CIDEr-D 奖励之差构成优势，乘以采样序列的对数概率，进行策略梯度更新。奖励缓存仅保存训练参考文本及其 n-gram 文档频率，不缓存策略轨迹或固定预测奖励。微调轮次按验证集 CIDEr-D 选择，再将原始交叉熵模型与 SCST 模型在相同清单上分别进行 Greedy/Beam 推理和完整评价，同时核对初始化模型的训练数据来源。

选做二采用 **LLM-as-Judge** 对食物图像和五种模型生成的描述进行联合评价，从内容正确性、覆盖度、幻觉控制和语言流畅度四个维度给出 1—5 分及理由。模型通过 OpenAI 兼容接口调用，固定提示词、模型和生成参数；对每张图片计算传统文本指标，分析其与 LLM 评分的 Pearson、Spearman 相关性。拟对部分样本补充人工标注，再进行人工评分一致性分析；没有真实人工评分时不报告该项结果。

选做三构建单图像营养估计 Agent，使用支持 RGB 输入和工具调用的视觉语言模型识别食物及烹饪状态，并调用独立重量模型和营养数据库。主方案不额外微调 Agent 所用的大模型，与任务二的 LoRA 训练保持独立。

重量工具冻结 DINOv2-Small，将 CLS 特征与 Patch 均值特征拼接为 768 维向量，仅用训练集整餐重量标签拟合 StandardScaler 和 Ridge 回归器，不训练 DINOv2。通过训练集内的分组交叉验证选择正则化系数，同一菜品的相关视角使用共享分组，避免跨组泄漏；同时设置训练集平均重量预测作为简单基线，另在验证集评价选定模型。

营养工具读取 USDA SR Legacy 与 FNDDS 固定版本数据，按食品名称及生熟、烹饪状态检索营养密度和标准份量。当前主方案直接使用原始数据库，不要求营养校准。基于训练集单项餐标签的类别营养密度统计作为可选扩展，启用时独立说明其样本覆盖范围和验证结果。

Agent 先看图调用 `lookup_nutrition`，再调用不接收语义参数、绑定原始 RGB 图片的 `estimate_weight`。存在影响食品匹配的歧义时，允许进行一次裁剪复核或纠正识别后重新查表，总重量保持不变。最后调用 `calculate` 选择食品记录并给出各项相对重量，由程序归一到预测整餐重量，按营养密度计算热量和三大营养素。正常流程为三次模型请求，最多五次；使用简单的有界工具调用循环，不引入 LangGraph。实验在同一模型服务下比较 `direct` 直接生成与 `agent` 工具辅助生成，记录中间观察和工具结果，最终数值由工具计算。

# 六、评价方案

任务一采用课程规定的全部五种指标，即 BLEU、METEOR、ROUGE-L、CIDEr-D 和 SPICE。从词级匹配、序列结构、共识描述以及语义关系等不同维度综合评价模型输出。模型选择时主要使用验证集 CIDEr-D，同时报告全部五项结果。SCST 实验在相同解码设置下报告各指标相对交叉熵模型的变化，分析奖励指标与其他指标之间的取舍，不预设所有指标同时提升。

任务二将文本语义和数值预测分开评价。食物名称统计 micro-F1 和按食物类别计算的 macro-F1；重量、热量、蛋白质、脂肪和碳水分别计算 MSE，并分别报告有效预测覆盖率。数值 MSE 只使用对应字段存在且为有限数值的预测，缺失或无法解析的字段不填零。文本评价将食物实体转换为统一模板，例如将 `["beef", "potato"]` 转换为 `A meal contains beef and potato.`，再计算五种文本指标。

结构正确性方面进一步分别报告 JSON 解析率、Schema 有效率、字段完整率以及重量一致性。解析失败或字段不合法的结果保留原始输出和错误信息，不进行自动修复。

LLM-as-Judge 分别报告四个维度的评分分布、有效评分数量，以及与传统指标的 Pearson、Spearman 相关系数。人工一致性分析仅使用实际完成人工标注的同一批描述。

营养估计实验比较直接生成与工具辅助生成的食物名称 micro-F1、macro-F1，以及重量、热量、蛋白质、脂肪和碳水五项 MSE、MAE。Agent 数值误差仅统计成功且 Schema 有效的预测，同时以完整评价清单为分母报告数值覆盖率、失败率和缺失预测数；失败预测不补零，食物 F1 中按空预测处理。该条件与任务二按各字段有限数值分别统计的方式分别记录，比较误差时同时检查覆盖率。另报告各项重量与总重量的偏差、平均推理耗时、模型请求次数、工具调用次数及接口返回的 Token 用量。

所有新增实验先在验证集检查流程、选择配置，再冻结模型、数据库、映射、提示词和生成参数进行最终测试。测试标签仅用于评分，不进入模型提示词、工具输入或参数选择。已经运行的测试结果按原配置保留，后续实验如有配置变化须分别记录。

除任务指标外，还记录每个模型的可训练参数量、总参数量、训练时间、单样本或 Batch 推理时间以及峰值显存，从效果和计算成本两个方面进行比较。

# 十、实施可行性与可能的问题

从计算资源上看，本作业拥有 4 张 RTX 4090。任务一中的 ResNet-50、ViT-B/16、GRU 和中小型 Transformer 均属于可在单张 4090 上训练的规模，因此可将多卡资源主要用于并行运行不同模型实验。Qwen3-VL-4B 等模型规模明显更大，但作业采用冻结基础权重的 LoRA 方式，并可结合 BF16、Gradient Checkpointing 和 Gradient Accumulation，因此整体具有较好的工程可行性。

数据方面，Food-500 Cap 已提供公开训练和测试描述文件，官方数据规模足以完成五种结构的比较实验。[GitHub](https://github.com/aaronma2020/Food500-Cap) 任务二采用教学云平台提供的 Nutrition5k 数据，通过数据准备模块统一字段并保留原始划分，图片路径和训练参数由 YAML 配置管理。

任务二最大的技术难点是单张 RGB 图片中的重量和营养值并不能完全由视觉外观唯一确定，因此模型的数值误差可能明显大于食物类别预测误差。本作业将这一问题作为实验分析内容，保留模型原始预测，并对直接生成和两阶段生成进行控制变量比较，分析错误主要来自食物识别还是数值推断。

工具辅助营养估计还可能受到食物识别粒度、烹饪状态及营养数据库匹配误差的影响。整道成品菜与标注中的原料列表可能存在粒度差异，工具计算正确也不能保证识别和营养估计准确。因此需要结合调用轨迹分别分析视觉估重、食品检索和重量分配的误差，不预先保证 Agent 优于直接生成。

SCST 直接优化 CIDEr-D，可能对 METEOR、SPICE 等指标产生不同方向的影响；LLM-as-Judge 也可能存在评分偏好和接口失败。实验将完整报告指标变化、有效样本数和失败情况，避免只选取有利指标。模型训练、离线回归与大模型服务可分时安排，防止服务显存占用影响训练运行。

另一个风险是 SPICE 和 METEOR 等指标依赖 Java 组件，因此在正式训练前对 Python、CUDA、Java、模型依赖和评测组件统一进行环境检查，以避免模型训练完成后无法执行评测。

# 十一、预期成果

本作业完成后预期形成完整的实验代码库，包括 Food-500 Cap 和 Nutrition5k 数据处理接口、五种自主实现的图像描述模型、五种图像描述评价指标、结构化膳食记录 Schema 与校验器、Qwen3-VL/Qwen2.5-VL LoRA 与 zero-shot 推理模块、草稿复核、SCST 强化学习微调、LLM-as-Judge 评价、独立重量回归器和营养估计 Agent，以及统一的训练、推理和结果管理程序。

每组正式实验均保存运行配置、随机种子、模型预测以及最终指标，保证不同模型实验具有基本可重复性。代码仓库不提交原始数据集、大模型基础权重或本机绝对路径；大模型实验仅保存 LoRA Adapter 或配置说明。

最终实验重点比较五种图像描述结构、自建模型与预训练视觉语言模型、Qwen zero-shot 与 LoRA、直接生成与分阶段及草稿复核策略、交叉熵与 SCST，以及营养直接生成与工具辅助生成。结合 Judge 一致性分析，从描述质量、结构有效性、食物识别、数值误差、失败率和计算成本等方面说明各方法的特点与局限。
