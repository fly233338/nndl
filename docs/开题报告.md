# 开题报告

## 一、题目和作业概述：基于深度学习的食物图像描述与膳食信息生成

这次课程设计围绕食物图像理解展开，主要包括食物图像描述和结构化膳食记录生成两项任务，并选择强化学习优化和大模型评价两项选做实验。

- **任务一：食物图像描述。** 使用 Food-500 Cap 数据集，实现并比较 ResNet+GRU、注意力+GRU、CNN+Transformer、GAT+Transformer 和 ViT+Transformer 五种模型。在统一评价条件下选取综合表现最好的方法，以其为起点进一步改进模型，并分析改进前后的效果。
- **任务二：结构化膳食记录生成。** 使用 Nutrition5k 数据，比较自建图像描述模型与经过 LoRA 微调的 Qwen3-VL、Qwen2.5-VL 模型，生成包含食物名称、重量、热量和三大营养素的 JSON。在直接生成的基础上，探索多阶段输出和多阶段、多任务训练，分析任务分解与联合训练对结果的影响。
- **选做实验。** 尝试 SCST、GRPO 等强化学习方法，比较其与交叉熵训练的差异；使用 LLM-as-Judge 评价描述质量，并结合传统指标、人工评价和具体案例分析模型的优缺点。

各项实验会记录数据划分、训练配置、模型预测和评价结果，并结合效果、输出有效性和计算成本进行分析。项目重点是通过基线比较发现问题、开展改进并验证效果，具体改进方案根据后续实验结果确定。

## 二、任务描述

课程设计包括食物图像描述和结构化膳食记录生成两项主要任务，选做部分为强化学习优化和 LLM-as-Judge。

### 任务一：食物图像描述

任务一使用 Food-500 Cap 数据集，根据输入的食物图片生成自然语言描述。我会实现并比较五种图像描述模型，使用 BLEU、METEOR、ROUGE-L、CIDEr-D 和 SPICE 五种指标评价生成结果。

具体包括以下五种模型：

| 模型 | 视觉表示 | 文本生成模块 | 主要研究内容 |
|---|---|---|---|
| Model 1 | ResNet-50 全局特征 | GRU Decoder | 建立经典 CNN-RNN 基线 |
| Model 2 | ResNet-50 网格特征 | 视觉自注意力 + 加性注意力 + GRU | 研究局部视觉区域和显式注意力的作用 |
| Model 3 | ResNet-50 网格特征 | Transformer Encoder + Decoder | 研究全注意力序列建模 |
| Model 4 | 图结构网格特征 | GAT + Transformer Decoder | 研究食物局部区域之间的空间关系建模 |
| Model 5 | ViT-B/16 Patch 特征 | Transformer Decoder | 比较 CNN 与视觉 Transformer 表示能力 |

为了尽量公平地比较模型结构，五种模型使用相同的数据划分、图像预处理、文本词表、模型选择规则和 Greedy Search/Beam Search 解码设置。不同模型在训练超参数上的差异会记录在配置中。

完成基线比较后，主要根据验证集 CIDEr-D，并结合其他指标及生成案例，选出综合表现最好的模型作为进一步研究的起点。后续针对实验中发现的问题开展模型改进，通过改进前后对照和必要的消融实验分析各项改动的作用，不在开题阶段预先限定具体方案。

### 任务二：结构化膳食记录生成

任务二要求根据食物图片生成符合预定格式（Schema）的 JSON，至少包含食物列表 `items`（含名称和重量）、总重量 `total_weight_g`、总热量 `total_calories_kcal`，以及蛋白质、脂肪和碳水化合物三个营养字段。课程要求比较自建图像描述模型与经过全量微调或参数高效微调的多模态预训练模型，评价时使用任务一的文本指标和 F1、MSE 等结构化指标。

针对任务二，我准备设置以下基线与探索方向：

- **方法 A：自建图像描述模型。** 从任务一中选取验证集 CIDEr-D 表现较好的模型，将训练目标换成规范化的 JSON 序列，让模型直接从图像生成膳食记录。这里使用独立的可逆字符级分词器，保留 JSON 标点、小数和中文字符。
- **方法 B：Qwen3-VL-4B + LoRA 直接生成。** 使用预训练视觉语言模型 `Qwen/Qwen3-VL-4B-Instruct`，在教学云平台提供的 Nutrition5k 数据上进行 LoRA 微调，再通过固定提示词一次生成完整 JSON。
- **方法 C：Qwen3-VL-4B + LoRA 多阶段生成。** 在方法 B 的基础上探索多阶段输出，例如先生成食物组成，再生成重量和营养信息。同时探索与阶段划分相配合的多任务训练，研究不同子任务之间的信息共享和相互影响。具体阶段划分及训练组织方式根据实验结果进一步确定。
- **方法 D：Qwen2.5-VL-3B + LoRA。** 使用 `Qwen/Qwen2.5-VL-3B-Instruct` 作为对照，比较不同代际和参数规模的视觉语言模型在任务中的表现。

补充未加载 LoRA 适配器的原始 Qwen 模型进行 zero-shot 对照，分析领域微调的作用。主要围绕直接生成与多阶段生成、单任务与多任务训练开展比较，并结合食物识别、数值预测和输出格式中的错误进一步改进。

### 任务三：选做实验

选做部分包括强化学习优化和大模型评价描述质量。强化学习实验以已完成监督训练的模型为起点，尝试不同优化方法与奖励设置；LLM-as-Judge 实验从多个维度评价描述，并分析其与传统指标及人工判断的一致性。具体方案见第五节。

5. **选做实验与分析。** 比较交叉熵训练与所选强化学习方法，研究大模型评分与传统指标及人工判断的一致性。结合效果和计算成本，通过对照、消融及成功与失败案例分析各项改进的作用与局限。

## 四、相关工作

### 图像描述方法

图像描述生成结合了计算机视觉和自然语言处理。早期方法通常采用编码器—解码器结构：先用 CNN 提取图像特征，再用循环神经网络逐词生成描述。Vinyals 等人的 *Show and Tell* 是其中的代表，通过 CNN 编码图像，并训练循环网络生成与图像对应的文本。[2]只使用一个全局图像向量，很难充分描述图中的不同区域。为了解决这个问题，*Show, Attend and Tell* 引入视觉注意力，让模型在生成不同词语时关注不同区域。[3] 我设计的 Model 2 借鉴了这一思路，结合局部视觉特征、注意力机制和循环解码器生成描述。

Transformer 使用自注意力处理序列，能够建模较长距离的依赖，也便于并行训练。[4] Vision Transformer 则将图像划分成多个图像块（Patch），并将其作为视觉 Token 序列处理。[5] 在图像描述任务中，CPTR 进一步使用 Transformer 处理图像和文本序列。[6] 因此，我准备分别使用 CNN 和 ViT 提取视觉特征，再连接 Transformer 解码器，比较两种视觉表示的效果。食物图片中的不同区域也有空间关系，例如主菜和配菜的位置关系。Graph Attention Network（GAT）使用注意力为邻居节点分配不同的聚合权重，可以处理图结构中的局部关系。[7] 于是，我在 Model 4 中将视觉网格位置作为图节点，按八邻域连接，再利用 GAT 和 Transformer 解码器生成描述，考察空间关系建模是否有帮助。

### 食物场景与视觉语言模型

Food-500 Cap 是面向食物场景的细粒度图像描述基准，描述中包含食材、形态和颜色等信息。该工作也指出，通用视觉语言模型在食物描述上仍面临困难。[1] 这为在食物数据上比较不同描述模型提供了依据。近年来，视觉语言模型也能够直接处理图像和文本并生成结构化信息。Qwen2.5-VL 是其中的一个例子。考虑到全量微调的成本，我准备使用 LoRA：冻结预训练参数，在部分线性层中加入可训练的低秩矩阵，减少需要更新的参数量。这样可以在现有计算资源下尝试对 Qwen 模型进行领域适配。

### 强化学习与大模型评价

强化学习可以在交叉熵训练后直接优化生成结果的评价指标。SCST 使用当前模型的解码结果作为奖励基线，[8] GRPO 根据同一输入的一组采样输出计算相对奖励；[9] 此外，还可以调研 PPO、REINFORCE 等策略梯度方法。[10][11] 本项目将根据任务特点和计算资源选择适合的方法进行尝试，分析奖励指标、语义质量和训练成本之间的关系。

LLM-as-Judge 使用大模型对生成结果进行评价，可以补充传统文本匹配指标，但也可能存在位置偏好、长度偏好等问题。[12] 本项目将把这一思路用于食物图像描述，设计明确的评价维度，并通过匿名评价、顺序交换和少量人工复核检查评分的一致性。

## 五、技术方案

这里将把图像描述和膳食 JSON 生成作为独立实验，使用各自的运行入口和结果目录；强化学习和 LLM-as-Judge 分别用于模型优化和结果分析。数据读写、配置和评价工具可以在实验之间共用。

### 数据准备

数据处理部分分别适配 Food-500 Cap 和 Nutrition5k。Food-500 Cap 模块读取 Parquet 格式的图像和描述，去重并合并参考描述后，再划分训练集与验证集，生成 `train.jsonl`、`val.jsonl`、`test.jsonl` 和 `dataset_info.json`。训练词表仅从训练集建立，保存为 `vocab.json`，验证和测试时固定使用。Nutrition5k 使用教学云平台提供的数据，保留原始训练、验证和测试划分及重量、营养标签，并将字段转换成内部格式。图片路径等配置由 YAML 管理。

### 任务一：图像描述模型

任务一的五种基线模型共用数据集接口、分词器和训练流程，视觉编码器默认加载 ImageNet 预训练参数并冻结。各模型的主要区别如下：

- Model 1 使用 ResNet-50 全局特征作为 GRU 的视觉条件。
- Model 2 保留二维网格特征，先进行视觉自注意力建模，再通过加性注意力计算每个生成步骤与局部区域的相关性。
- Model 3 将网格特征映射为视觉 Token，加入二维位置编码，再通过 Transformer 编码器和自回归解码器生成描述。
- Model 4 将二维网格构造成八邻域图，用两层 GAT 聚合后，将结果提供给 Transformer 解码器。
- Model 5 去掉 ViT-B/16 的 CLS Token，将 Patch Token 直接送入 Transformer 解码器，不额外叠加视觉 Transformer 编码器。

训练时使用 Teacher Forcing 和逐 Token 的交叉熵损失，并根据验证集 CIDEr-D 保存最佳模型。推理时提供贪心搜索和束搜索，各模型使用相同的最大生成长度、特殊 Token 和束宽。测试预测保存为以下格式：

```json
{
  "image_id": "xxx",
  "references": ["reference caption"],
  "prediction": "generated caption"
}
```

随后使用同一套程序计算五种评价指标，避免评价实现不同影响模型比较。在五种基线中选取验证集综合表现最好的模型，结合预测案例分析其主要问题，再开展模型改进和对照验证。具体改进结构与训练方案将在后续实验中确定。

### 任务二：膳食 JSON 生成

任务二需要先定义结构化输出格式，例如：

```json
{
  "items": [
    {
      "name": "food",
      "weight_g": 64.0
    }
  ],
  "total_weight_g": 64.0,
  "total_calories_kcal": 103.3,
  "protein_g": 2.9,
  "fat_g": 6.9,
  "carbohydrate_g": 10.6
}
```

模型的原始输出会被保留。解析器和校验器分别负责解析 JSON 和检查格式，包括必需字段、字段类型、非负有限数值及未定义字段；数值不接受 bool、NaN 或 Infinity。各项重量之和与总重量的偏差单独统计，不作为格式错误。

预测结果及解析信息保存在 JSONL 文件中，评价指标另存为 JSON。多阶段生成保留各阶段输出与运行配置，用于分析错误发生在哪个阶段，以及前一阶段的预测如何影响后续结果。评测阶段不会自动修复模型输出。

Qwen3-VL 和 Qwen2.5-VL 使用 LoRA 微调，不进行量化，优先采用 BF16。LoRA 主要插入注意力相关的线性投影层，具体 `target_modules` 根据模型模块名称确定。训练时冻结模型主干，主要保存 LoRA 适配器，以减少训练显存和提交文件体积。

对于 Qwen3-VL，在直接生成的基础上探索多阶段输出，并研究多阶段、多任务训练。可以将完整记录生成、食物信息生成和营养信息生成作为相关子任务，比较不同训练组织方式对各项指标的影响。阶段划分、任务组合及训练设置将根据基线表现和错误分析进一步确定。

实验中分别考察推理方式和训练方式的变化：比较直接生成与多阶段生成时，尽量复用同一训练检查点；比较单任务与多任务训练时，记录并尽量匹配训练预算，避免混淆不同因素带来的影响。零样本实验沿用对应微调实验的数据、提示词和评价流程。

### 选做一：强化学习优化

强化学习实验以任务一中选定模型的交叉熵训练检查点为起点，尝试直接优化 CIDEr-D 等生成指标，并与继续使用交叉熵训练的结果比较。可探索的方法包括 SCST、GRPO，以及 PPO、REINFORCE 等策略梯度方法；这些方法作为候选方向，根据实现难度、训练稳定性和资源开销选择开展，不预先承诺全部实现。

奖励可以采用单一描述指标，也可以探索结合实体正确性等因素的综合奖励。具体算法和奖励设置先在验证集选择，最终在相同数据划分与解码条件下比较。分析时同时关注奖励指标、其他文本指标、语义质量和训练成本，检查是否存在只提高某项指标却损害描述质量的情况。

### 选做二：LLM as a judge

LLM-as-Judge 主要用于评价图像描述，并分析模型改进和强化学习带来的变化。按照预先确定的规则抽取固定图像子集，覆盖不同食物类别和餐盘复杂度，在同一批图片上比较基线模型、改进模型及强化学习模型的输出。

评价模型读取原图与匿名描述，从以下四个维度给出 1—5 分及简短理由，分数越高表示质量越好：

| 维度 | 评价重点 |
|---|---|
| 内容正确性 | 食物、颜色、形态及关系等描述是否得到图像支持 |
| 内容覆盖度 | 是否描述主要食物和重要细节，是否存在明显遗漏 |
| 幻觉控制 | 是否避免添加图像不支持的食材、属性或关系 |
| 语言流畅度 | 表达是否自然、清楚，是否存在重复或语句不完整 |

提示词中给出统一评分依据，区分明显错误、部分准确和基本准确等情况，并要求理由指出具体内容，避免仅凭描述长度或措辞华丽程度评分。对于图像无法确认的细节，允许评价模型说明不确定性。

在分维度评分之外，对部分改进前后的描述开展成对比较，允许给出平局，并交换两条描述的展示顺序，检查偏好是否稳定。评价时隐藏模型名称，固定评价模型版本、提示词和生成参数；提示词先在验证集确定，再用于固定评价子集。

结果分析包括大模型评分与传统指标的 Pearson、Spearman 相关性，成对比较的胜率、平局率及顺序交换一致性，并对少量样本补充人工复核。重点分析“传统指标提高但语义质量未改善”等不一致案例。有效评分数量、调用失败和无法判断的样本单独记录；实际完成人工标注后再报告人工一致性结果。

## 六、评价方案

### 任务一及强化学习评价

任务一采用课程规定的 BLEU、METEOR、ROUGE-L、CIDEr-D 和 SPICE 五种指标。BLEU 主要考察 n-gram 精确率，METEOR 进一步考虑词级匹配，ROUGE-L 基于最长公共子序列；CIDEr 使用 TF-IDF 对 n-gram 加权，CIDEr-D 又加入长度和重复惩罚；SPICE 则从场景图中的对象、属性和关系评价语义。选择模型时主要参考验证集 CIDEr-D，最终报告全部五项指标。

模型改进和强化学习实验使用相同的评价流程及解码设置，报告各指标相对基线的变化。通过对照和必要的消融实验分析各项改动的作用，关注奖励指标与其他指标之间是否存在取舍，并结合案例说明提升或退化出现在哪些方面。

### 任务二评价

任务二分别评价食物名称、数值预测和输出格式。食物名称先进行规范化，再计算 micro-F1 和按类别计算的 macro-F1；重量、热量、蛋白质、脂肪和碳水分别计算 MSE，并报告各字段的有效预测覆盖率。MSE 只统计对应字段存在且为有限数值的预测，缺失或无法解析的字段不填零。为了计算文本指标，先将食物名称转换成统一模板，例如把 `["beef", "potato"]` 转换为 `A meal contains beef and potato.`，再计算任务一使用的五种指标。

格式评价包括 JSON 解析率、Schema 有效率、字段完整率和重量一致性。解析失败或字段不合法时，保留原始输出和错误信息。

### 大模型评价与结果分析

LLM-as-Judge 实验报告四个维度的评分分布、有效评分数量，以及与传统指标的相关系数。成对比较补充报告胜率、平局率和顺序交换一致性；人工一致性分析只使用实际完成人工标注的同一批描述。结合分数一致和不一致的案例，分析评价方法的适用范围。

任务二结合多阶段的中间输出，分析食物识别、数值预测和格式错误之间的关系，比较不同训练方式对各子任务的影响。各项实验同时记录训练和推理成本，保留成功与失败案例，用于说明改进的效果及局限。
